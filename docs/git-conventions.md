# Git 컨벤션

## 브랜치명

`<type>/#<이슈번호>/<작업내용>`

예: `feat/#13/input-develop`

## 커밋 메시지

`<type>(<변경범위>): <설명>`

예: `feat(worklog): input 개발`

`<변경범위>`는 생략하지 않고 항상 씁니다 (예: 패키지명, 앱명, `config`, `root` 등 변경이 속한 영역). 변경이 여러 영역에 걸쳐 있어 범위 하나로 좁히기 어렵다면, 커밋 자체를 영역별로 나누는 것을 먼저 고려합니다.

## PR / 이슈 제목

`<Type>(<변경범위>): #<이슈번호> <설명>`

예: Feat(web): #13 어쩌구저쩌구`

## 타입

| 타입     | 용도                                |
| -------- | ----------------------------------- |
| Init     | 프로젝트/기능 초기 세팅             |
| Fix      | 버그 수정                           |
| Style    | 스타일/포맷팅 변경 (로직 변화 없음) |
| Feat     | 새 기능 추가                        |
| Refactor | 리팩토링                            |
| Docs     | 문서 변경                           |

브랜치명·커밋 메시지의 `<type>`은 소문자(`feat`, `fix`, `style`, `refactor`, `docs`, `init`)를 쓰고, PR/이슈 제목의 `<Type>`은 첫 글자를 대문자로 씁니다 (예: `Feat`, `Fix`).

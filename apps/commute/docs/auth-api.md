# 출근부 인증 API

출근부 로그인·회원가입 화면(`app/(auth)`, `/login`·`/signup`)이 서버와 주고받는 API를 정리한 문서입니다. 관리자 화면 API는 [`admin-api.md`](admin-api.md), 근로학생 화면 API는 [`student-api.md`](student-api.md)에 있습니다. 서버가 아직 없어서, 서버가 보낼 모양 그대로의 목업으로 동작합니다.

- 프론트 코드: `apps/commute/src/app/(auth)/_apis/` (리소스마다 파일 하나, 함수마다 위에 메서드·경로 주석)
- 목업: `apps/commute/src/app/(auth)/_apis/mock/`
- 서버를 붙이면 `_apis` 함수 안만 실제 요청으로 바꿉니다. 화면 코드는 그대로 둡니다

## 공통 규칙

[관리자 API의 공통 규칙](admin-api.md#공통-규칙)과 같습니다. 다른 점만 적습니다.

| 항목 | 규칙                                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------------------- |
| 경로 | `/auth`로 시작합니다. 로그인하기 전에 부르는 API라 관리자(`/admin`)와 근로학생(`/me`) 어디에도 속하지 않습니다 |
| 역할 | 근로장학생은 `"STUDENT"`, 관리자는 `"ADMIN"`입니다. 화면에서 고르지 않고 서버가 로그인 응답으로 알려 줍니다    |
| 메일 | 학교 메일(`@konkuk.ac.kr`)만 받습니다. 프론트가 보내기 전에 검사하지만, 서버도 같은 규칙으로 검사해야 합니다   |

## 한눈에 보기

| 메서드 | 경로                                | 하는 일                            | 쓰는 화면 |
| ------ | ----------------------------------- | ---------------------------------- | --------- |
| POST   | `/auth/login`                       | 학교 메일과 비밀번호로 로그인      | 로그인    |
| GET    | `/auth/work-departments`            | 근무 부서 목록                     | 회원가입  |
| POST   | `/auth/email-verifications`         | 학교 메일로 인증번호 보내기        | 회원가입  |
| POST   | `/auth/email-verifications/confirm` | 인증번호 확인, 인증 토큰 받기      | 회원가입  |
| POST   | `/auth/signup`                      | 근로장학생 계정 만들기 (승인 대기) | 회원가입  |

## 로그인 `login`

### POST `/auth/login`

```json
{ "email": "gildong@konkuk.ac.kr", "password": "password1234" }
```

성공하면 `200`과 로그인한 사용자를 보냅니다. 프론트는 `role`을 보고 근로장학생은 학생 홈(`/`), 관리자는 관리자 홈(`/dashboard`)으로 보냅니다.

```json
{ "userId": 1, "name": "홍길동", "role": "STUDENT" }
```

실패하면 아래 오류 코드를 보냅니다.

| 상태  | `code`                | 언제                                       | 화면                                         |
| ----- | --------------------- | ------------------------------------------ | -------------------------------------------- |
| `401` | `INVALID_CREDENTIALS` | 메일이 없거나 비밀번호가 틀림              | 이메일 또는 비밀번호가 틀렸습니다.           |
| `403` | `PENDING_APPROVAL`    | 메일·비밀번호는 맞지만 가입 승인 전인 계정 | 승인 대기 화면(`/pending-approval`)으로 이동 |

```json
{ "code": "INVALID_CREDENTIALS" }
```

- 메일이 없는 것과 비밀번호가 틀린 것은 **구분하지 않습니다**. 어느 메일이 가입돼 있는지 밖에서 알 수 없게 하기 위해서입니다
- 승인 대기는 비밀번호까지 맞을 때만 알려 줍니다. 비밀번호가 틀리면 승인 대기 계정이라도 `INVALID_CREDENTIALS`입니다

### 목업 계정

목업에서 로그인할 수 있는 계정입니다. 비밀번호는 모두 `password1234`입니다.

| 메일                   | 이름   | 역할      | 상태      |
| ---------------------- | ------ | --------- | --------- |
| `gildong@konkuk.ac.kr` | 홍길동 | `STUDENT` | 승인됨    |
| `admin@konkuk.ac.kr`   | 김정보 | `ADMIN`   | 승인됨    |
| `newbie@konkuk.ac.kr`  | 박새봄 | `STUDENT` | 승인 대기 |

근로장학생 계정(홍길동)은 근로학생 화면 목업의 본인(`GET /me`)과 같은 사람입니다.

## 회원가입 `signup`

가입 화면에서 역할을 고르지 않습니다. 가입한 계정은 모두 **근로장학생 승인 대기** 계정이 되고, 관리자가 승인해야 로그인할 수 있습니다. 선생님(관리자)도 같은 화면으로 가입한 뒤 서버가 역할을 `ADMIN`으로 바꾸고 승인합니다. 가입이 끝나면 프론트는 승인 대기 화면(`/pending-approval`)으로 보냅니다.

순서: 근무 부서 목록 받기 → 인증번호 보내기 → 인증번호 확인(인증 토큰 받기) → 가입(인증 토큰 함께 보냄)

### GET `/auth/work-departments`

근로장학생이 일하는 학교 부서 목록입니다. 학과(`department`)와 다릅니다.

```json
{
  "workDepartments": [
    { "workDepartmentId": 1, "name": "정보운영팀" },
    { "workDepartmentId": 2, "name": "장학관리팀" }
  ]
}
```

목업은 정보운영팀, 장학관리팀, 도서관, 학생지원팀, 교무팀, 총무팀, 기획팀, 입학관리팀, 취업지원팀 9개입니다.

### POST `/auth/email-verifications`

학교 메일로 6자리 인증번호를 보냅니다. 다시 받기도 같은 요청이고, 이전 번호는 쓸 수 없게 됩니다.

```json
{ "email": "gildong@konkuk.ac.kr" }
```

성공하면 `200`과 인증번호가 유효한 시간(초)을 보냅니다. 서버 시계와 휴대폰 시계가 달라도 타이머가 어긋나지 않게, 만료 시각 대신 남은 초를 주고 프론트가 받은 때부터 셉니다.

```json
{ "expiresInSeconds": 300 }
```

| 상태  | `code`               | 언제             | 화면                                         |
| ----- | -------------------- | ---------------- | -------------------------------------------- |
| `409` | `ALREADY_REGISTERED` | 이미 가입된 메일 | 인증번호를 보내지 않고 로그인 링크를 보여 줌 |

### POST `/auth/email-verifications/confirm`

```json
{ "email": "gildong@konkuk.ac.kr", "code": "123456" }
```

맞으면 `200`과 가입할 때 보낼 인증 토큰을 보냅니다.

```json
{ "verificationToken": "..." }
```

| 상태  | `code`         | 언제                                     | 화면                        |
| ----- | -------------- | ---------------------------------------- | --------------------------- |
| `400` | `INVALID_CODE` | 인증번호가 틀림 (보낸 적 없는 메일 포함) | 인증번호가 맞지 않다고 안내 |
| `400` | `EXPIRED_CODE` | 인증번호를 받은 지 5분이 지남            | 다시 받으라고 안내          |

### POST `/auth/signup`

```json
{
  "name": "홍길동",
  "email": "gildong@konkuk.ac.kr",
  "password": "password1234",
  "workDepartmentId": 1,
  "verificationToken": "..."
}
```

가입되면 본문 없이 `201`을 보냅니다.

| 상태  | `code`               | 언제                                                    | 화면                         |
| ----- | -------------------- | ------------------------------------------------------- | ---------------------------- |
| `400` | `EMAIL_NOT_VERIFIED` | 메일 인증을 하지 않았거나 인증 토큰이 그 메일 것이 아님 | 메일 인증을 다시 하라고 안내 |
| `409` | `ALREADY_REGISTERED` | 인증한 뒤 같은 메일로 이미 가입됨 (요청이 겹친 경우)    | 이미 가입된 메일이라고 안내  |

- 이름은 앞뒤 공백을 뺀 뒤 1자 이상, 비밀번호는 영문과 숫자를 섞어 8자 이상입니다. 프론트가 먼저 검사하지만 서버도 같은 규칙으로 검사해야 합니다

### 목업 동작

- 인증번호는 늘 `123456`입니다 (메일을 보내지 않습니다)
- 가입한 계정은 로그인 목업에 근로장학생 승인 대기 계정으로 바로 추가됩니다. 그 메일로 로그인하면 승인 대기 화면으로 갑니다
- 목업 데이터는 새로 고치면 처음으로 돌아갑니다

## 백엔드와 정해야 할 것

프론트가 임시로 가정해 둔 부분입니다. 정해지면 이 문서와 `_apis`를 함께 고칩니다.

- **로그인 상태 저장**: 로그인 뒤 서버가 무엇을 주는지(쿠키 / 토큰)와 프론트가 어디에 두는지. 페이지 보호·로그인 유지와 함께 정합니다. 지금은 로그인해도 아무것도 저장하지 않고, 모든 화면에 주소로 들어갈 수 있습니다
- **오류 응답 모양**: 위 표의 상태 코드(`401` 로그인 실패, `403` 승인 대기)와 본문 `{ "code": "..." }`는 모두 프론트가 가정한 값입니다
- **메일 대소문자**: 프론트는 메일을 소문자로 바꿔 보냅니다. 서버도 대소문자를 가리지 않고 계정을 찾아야 합니다
- **로그인 시도 제한**: 비밀번호를 여러 번 틀렸을 때 막을지와 그때의 오류 코드
- **관리자 지정**: 선생님도 회원가입 화면으로 가입하고, 서버가 그 계정의 역할을 `ADMIN`으로 바꾸고 승인하는 것으로 가정했습니다. 승인 전에는 근로장학생 승인 대기 목록에 함께 보입니다
- **인증 토큰**: `verificationToken`의 모양과 유효 시간. 인증 뒤 얼마 안에 가입해야 하는지
- **인증번호 다시 받기 제한**: 짧은 시간에 여러 번 받을 때 막을지와 그때의 오류 코드
- **회원가입 오류 상태 코드**: 위 표의 `400`·`409`도 프론트가 가정한 값입니다

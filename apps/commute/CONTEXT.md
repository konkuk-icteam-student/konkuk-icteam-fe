# 출근부 용어집

출근부(`apps/commute`) 코드·이슈·문서에서 쓰는 말을 정리한다. 같은 것을 가리킬 때는 여기 적힌 말만 쓴다.

## 근무

| 용어          | 코드 이름                                                                | 뜻                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 근무 인원     | `worker` (근무 인원 API)                                                 | 관리자 화면에서 근로장학생을 부르는 다른 이름. 서버 API 이름이 "근무 인원 목록·상세"이고, 관리자 근로장학생 목록 제목도 디자인대로 "근무인원 정보"라고 쓴다. 근로장학생과 같은 사람이다                                                                                                                                                                                                                                          |
| 근무          | `WorkShift` (근로학생 API), `WorkerShift`·`AttendanceShift` (관리자 API) | 근로장학생이 하루 오전 또는 오후에 배정받은 이어진 근무 구간. 30분 칸 배치를 묶은 것이고, 하루에 오전·오후 한 건씩까지 있다. 관리자 API는 한 사람의 기간 근무(`WorkerShift`)와 하루 모든 사람의 근무(`AttendanceShift`)로 나눠 받는다                                                                                                                                                                                            |
| 근무 상태     | `workStatusCode`                                                         | 근무가 어디까지 왔는지. 예정(`WK01`)·근무중(`WK02`)·근무 완료(`WK03`)·결근(`WK04`)                                                                                                                                                                                                                                                                                                                                               |
| 결근          | `WK04`                                                                   | 끝난 근무에 출근 체크를 하지 않은 것                                                                                                                                                                                                                                                                                                                                                                                             |
| 지각          | `late`                                                                   | 근무 시작 시각에서 5분(`LATE_GRACE_MINUTES`)을 넘겨 출근 체크한 것 (10:30 시작이면 10:35:00까지는 정상). 지각 시간은 유예를 빼지 않고 시작 시각부터 센다 (예: 10:30 시작 · 10:36 출근 → 6분 지각). 근무시간에서 빼지 않고 따로 센다. DB에는 출근 시각만 저장하고, 지각 여부와 지각 횟수·시간은 서버가 출근 시각으로 계산해 준다 (`attendanceStatusCode`, `lateCount`, `lateMinutes`). 대시보드 근태 색은 아직 시작 시각 기준이다 |
| 근태 이상     | `attendanceIssue`                                                        | 지각·결근처럼 근태가 정상이 아닌 것. 목록의 근태 이상 횟수(`totalAttendanceIssueCount`)는 그 달 지각과 결근을 합친 수로 본다 (서버 정의 확인 필요)                                                                                                                                                                                                                                                                               |
| 최대 근로시간 | `weeklyLimitMinutes`, `monthlyLimitMinutes`                              | 한 주·한 달에 일할 수 있는 최대 시간(분). 사람마다 다를 수 있고, 그 달 근로학생이 아니면 0이다                                                                                                                                                                                                                                                                                                                                   |
| 휴게          | `LUNCH_BREAK`                                                            | 11:30 ~ 13:00 점심시간. 이 시간에는 근무를 배정하지 않는다                                                                                                                                                                                                                                                                                                                                                                       |
| 근로대장      | —                                                                        | 한 근로장학생의 한 달 근무 완료 건을 날짜순으로 적은 표 ("교내근로장학생 근로대장"). 퇴근 기록이 없어 시작·종료·근무시간은 배정된 시간으로 적는다. 예정·결근 근무는 싣지 않으므로 월 총 근로시간은 그 달 누적 근무시간과 같다                                                                                                                                                                                                    |

## 계정 관리

| 용어            | 코드 이름 | 뜻                                                                                                                                                                                               |
| --------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 비밀번호 초기화 | —         | 관리자가 요청하면 근로장학생 학교 메일로 비밀번호 재설정 링크를 보내고, 근로장학생이 링크를 눌러 새 비밀번호를 정하는 것. 메일이 없으면 할 수 없다                                               |
| 계정 삭제       | —         | 관리자가 근로장학생 계정을 지우는 것. 시간표·근로대장·개인정보 등 그 근로장학생과 관련된 정보가 모두 지워지고 되돌릴 수 없다 ([ADR 0001](docs/adr/0001-account-deletion-removes-all-records.md)) |

## 사용자

| 용어       | 코드 이름                        | 뜻                                                                                                                      |
| ---------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 근로장학생 | `worker` (API), `STUDENT` (역할) | 출근부로 근무를 신청하고 기록하는 학생. 화면 문구에서는 "근로학생"으로 줄여 쓴다                                        |
| 관리자     | `ADMIN` (역할)                   | 근로장학생의 근무·신청·업무를 관리하는 직원(선생님). 회원가입 화면으로 가입한 뒤 서버가 역할을 관리자로 바꾸고 승인한다 |
| 역할       | `role`                           | 로그인한 사용자가 근로장학생인지 관리자인지. 서버가 로그인 응답으로 알려 주고, 화면에서 고르지 않는다                   |
| 학교 메일  | `email`                          | `@konkuk.ac.kr`로 끝나는 메일. 로그인 아이디로 쓴다                                                                     |
| 근무 부서  | `workDepartment`                 | 근로장학생이 일하는 학교 부서 (예: 정보운영팀, 장학관리팀). 회원가입 때 목록에서 고른다                                 |
| 학과       | `department`                     | 근로장학생이 다니는 학과 (예: 컴퓨터공학부). 근무 부서와 다르다                                                         |

## 인증

| 용어        | 코드 이름             | 뜻                                                                                                                                                                           |
| ----------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 로그인      | `login`               | 학교 메일과 비밀번호로 들어가는 것. 성공하면 역할에 따라 근로장학생은 학생 홈(`/`), 관리자는 관리자 홈(`/dashboard`)으로 간다                                                |
| 승인 대기   | `PENDING_APPROVAL`    | 회원가입은 했지만 관리자가 아직 승인하지 않은 계정. 로그인할 수 없고, 로그인하면 승인 대기 화면(`/pending-approval`)으로 보낸다                                              |
| 회원가입    | `signup`              | 이름·학교 메일·비밀번호·근무 부서로 계정을 만드는 것. 가입 화면에서 역할을 고르지 않고, 가입한 계정은 모두 근로장학생 승인 대기 계정이 된다. 선생님도 같은 화면으로 가입한다 |
| 메일 인증   | `emailVerification`   | 회원가입 때 학교 메일로 받은 인증번호(6자리, 5분 안)를 입력해 본인 메일인지 확인하는 것                                                                                      |
| 로그인 실패 | `INVALID_CREDENTIALS` | 메일이 없거나 비밀번호가 틀린 경우. 둘을 구분하지 않고 같은 문구로 안내한다                                                                                                  |
| 페이지 보호 | —                     | 로그인하지 않은 사용자나 역할이 맞지 않는 사용자를 다른 화면으로 보내는 것. 로그인 상태를 어디에 저장할지와 함께 따로 다룬다                                                 |
| 로그인 유지 | —                     | 브라우저를 닫아도 로그인 상태가 남는 것. 페이지 보호와 함께 따로 다룬다                                                                                                      |
